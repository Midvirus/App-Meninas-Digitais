Analisando as funções já presentes no `api_client.dart` contra o que efetivamente está sendo chamado na UI (telas em Flutter, como `loginPage.dart`, `pinboard.dart` e `users.dart`), identifiquei que o backend já está com 100% dos endpoints mapeados no `ApiClient`, mas a maior parte dessas funções ainda não possui interface gráfica (UI) ou gerenciamento de estado conectado no aplicativo.

Abaixo está o relatório detalhado das funções que ainda FALTAM ser integradas à interface do Flutter, bem como a estruturação sugerida para implementar cada bloco:

====================================================================
1. MÓDULO DE DESAFIOS (TUTORAS E TUTORANDAS)
====================================================================
Funções no ApiClient aguardando integração:
- `createChallenge` (Criar Desafio - Tutora)
- `listChallengesForTutoranda` (Listar Desafios - Tutoranda)
- `enviarResposta` (Responder Desafio - Tutoranda)
- `minhasRespostas` (Ver Respostas Enviadas - Tutoranda)
- `respostasDoDesafio` (Ver Respostas de um Desafio - Tutora)
- `feedbackResposta` (Dar Feedback / Aprovar - Tutora)
- `destaqueResposta` (Destacar Resposta - Tutora)
- `progressoDesafio` (Ver estatísticas de progresso - Tutora)
- `removerDesafio` (Excluir Desafio - Tutora/Admin)

Como estruturar no Flutter:
- Estado (Providers/Controllers): Criar um `DesafioController` ou `DesafioProvider` para gerenciar a lista de desafios ativos e o carregamento das respostas.
- Telas - Visão da Tutora:
  - `DesafiosTutoraScreen`: Um ListView mostrando os desafios criados. Um FloatingActionButton (FAB) para abrir a tela de criação.
  - `CriarDesafioScreen`: Formulário contendo Título, Descrição, Nível de Dificuldade, Prazo e Tipo de Resposta. Salva usando `createChallenge`.
  - `DetalhesDesafioTutoraScreen`: Ao clicar em um desafio, mostra o `progressoDesafio` e uma lista das respostas submetidas (`respostasDoDesafio`).
  - Ao clicar em uma resposta, abrir um BottomSheet para enviar feedback (`feedbackResposta`) ou marcar como destaque (`destaqueResposta`).
- Telas - Visão da Tutoranda:
  - `DesafiosTutorandaScreen`: Exibe os desafios abertos (`listChallengesForTutoranda`).
  - `ResponderDesafioScreen`: Formulário contendo campo de texto, input de link externo e botão para upload de arquivo (`enviarResposta`).
  - `MinhasRespostasScreen`: Lista de status ("Pendente", "Aprovado") das submissões usando `minhasRespostas`.

- `registrarObservacao` (Criar anotação sobre a tutoranda)

Como estruturar no Flutter:
- Telas - Visão da Tutora:
  - Na tela atual de listagem de tutorandas (provavelmente vinculadas à tutora), ao clicar no perfil da menina, exibir uma aba "Observações".
  - Utilizar um `ListView` para exibir os itens de `listarObservacoes`.
  - Ter um campo de texto fixo no rodapé ou um botão que abre um dialog para digitar e chamar `registrarObservacao(tutorandaId, conteudo)`.

3. MÓDULO DE POSTAGENS AVANÇADO (PINBOARD)
====================================================================
Funções no ApiClient aguardando integração:
- `publicarComImagem` (Criar postagem contendo arquivo de imagem)

Como estruturar no Flutter:
- No arquivo `pinboard.dart` já existe a integração de texto (`publicar`), mas falta suporte à imagem.
- Incluir o pacote `image_picker`.
- No Dialog/Tela de criação de Post, adicionar um botão "Adicionar Imagem".
- Caso a usuária selecione uma imagem, fazer a requisição usando `ApiClient.publicarComImagem` passando o `filePath` ou `fileBytes`, substituindo a chamada atual de `ApiClient.publicar` (que é apenas texto).

  - `MuralScreen`: Uma tela nova, que pode ficar acessível no menu inferior. Deve chamar `ApiClient.mural()` para listar as respostas em destaque como um feed de realizações para inspirar a comunidade. O Admin/Tutora pode clicar para `removerDestaque` caso necessário.

ANÁLISE INVERSA: O QUE TEM NO FRONTEND E FALTA NO BACKEND
====================================================================
Após analisar os arquivos atuais do Flutter (`challenges.dart`, `notifications_page.dart`, `project_data_page.dart`), foram encontradas funcionalidades já desenhadas na UI que NÃO possuem endpoints correspondentes no OpenAPI/Backend atual:

1. GAMIFICAÇÃO E ESTATÍSTICAS DA TUTORANDA (PONTUAÇÃO E STREAKS)
- Frontend: No arquivo `challenges.dart`, existe uma forte lógica de gamificação. O app rastreia variáveis como `_totalPoints` (+10 por acerto, +2 por erro), `_totalAttempts`, `_correctAnswers`, `_currentStreak` (ofensivas seguidas) e `_bestStreak`. Há inclusive uma função `_showStatistics()` para exibir um resumo desses dados para a usuária.
- Faltando no Backend: Não existe nenhum endpoint no backend para persistir essas informações. Como está hoje, os pontos e estatísticas da usuária são perdidos assim que ela fecha o aplicativo.
- O que criar no Back:
  - Um esquema na tabela de `Usuario` (ou tabela separada `Gamificacao`) para armazenar: total de pontos, respostas corretas, ofensiva atual, ofensiva máxima.
  - Endpoints: `GET /api/tutoranda/estatisticas` e `PATCH /api/tutoranda/pontuacao` para atualizar o progresso quando ela responde um desafio.

2. DESAFIOS AUTOMATIZADOS DO SISTEMA (QUIZZES)
- Frontend: O `challenges.dart` possui uma lista de desafios de múltipla escolha gerados pelo próprio sistema ("Qual destas opções é uma linguagem de programação?"), com verificação imediata da resposta (`correctAnswer` e `justification`). 
- Faltando no Backend: O OpenAPI atual de `Desafio` é focado 100% em desafios criados por Tutoras (que exigem revisão manual). Não há uma rota para retornar "Quizzes Automáticos" do banco de dados e suas respectivas explicações (`justification`).
- O que criar no Back:
  - Um novo tipo de entidade no banco ou um campo de `isAutomated` no Desafio.
  - Endpoint: `GET /api/desafios-sistema` que traga quizzes com as opções e a resposta correta para que o frontend valide na hora e some os pontos.

3. SISTEMA DE NOTIFICAÇÕES (LIDAS / NÃO LIDAS)
- Frontend: Existe a tela `notifications_page.dart` (página de Notificações), que atualmente mostra apenas os Feedbacks Recebidos. O conceito de "Notificação" implica alertas de novas interações.
- Faltando no Backend: Embora seja possível usar a rota `minhasRespostas` para saber o que já tem feedback, não existe um controle de estado (ex: `isRead: boolean`) para a Tutoranda saber o que é uma notificação nova (uma bolinha vermelha na navbar).
- O que criar no Back (Opcional):
  - Um módulo dedicado de Notificações (`GET /api/notificacoes`) para avisar: "Nova publicação no mural", "Novo Desafio da sua Tutora", "Novo Feedback recebido", com função para marcar como lida (`PATCH /api/notificacoes/{id}/ler`).
